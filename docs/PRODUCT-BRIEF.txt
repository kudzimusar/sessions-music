==================================================
1. WHAT SESSIONS IS
==================================================

Sessions exists to make fragmented music infrastructure searchable, comparable, time-aware, bookable, payable and trusted.

The initial use case is extremely simple:

“I need somewhere to rehearse.”

Sessions should answer:

“Here are the rooms that actually fit your band, equipment requirements, budget, location and time. Pick one, reserve the slot and pay.”

A musician, band, choir, worship team, producer or other music professional should be able to:

Search → Compare → Select a time slot → Pay → Receive confirmation → Rebook.

On the supply side, a rehearsal-space provider should be able to:

List space → Define equipment → Set price → Expose available hours → Receive bookings → Earn money.

Providers are not limited to conventional commercial music studios.

Sessions should also make it possible for:

- churches
- schools
- universities
- arts centres
- companies
- recording studios with rehearsal rooms
- approved private facilities

to expose music-ready rooms during hours when those rooms would otherwise be unused.

This idle-capacity model is one of the key differentiators of Sessions.

==================================================
2. THE CORE TRANSACTION
==================================================

The fundamental marketplace loop is:

Provider exposes a valid rehearsal slot
→ musician searches for a suitable room
→ musician selects a time
→ musician books
→ payment succeeds
→ inventory is locked
→ provider earns revenue
→ Sessions retains its configured platform fee
→ the transaction creates booking and trust history.

Sessions is not merely showing phone numbers.

THE TRANSACTION WORKFLOW IS THE PRODUCT.

A directory can tell someone that a rehearsal room exists.

Sessions must tell them:

- whether the room is actually available
- when it is available
- how much it costs
- what equipment is included
- how many musicians it supports
- whether it has backup power
- where it is
- parking/access information
- its rules
- its cancellation terms
- its provider reliability
- whether it can be booked immediately
- how to pay
- whether it can be booked again next week

37. NORTH-STAR PRODUCT RULE
==================================================

Whenever considering a new feature, ask:

“Does this improve the discovery, evaluation, booking, payment, trust or monetisation of music infrastructure, and does it strengthen repeat Sessions transactions?”

If the answer is no, it probably does not belong in the current product.

Build the first version around one promise:

“I need somewhere to rehearse.”

Sessions should make finding, booking and paying for that room dramatically easier than calling studios, posting in groups or coordinating manually through WhatsApp.

Prove that first.

Then expand.
